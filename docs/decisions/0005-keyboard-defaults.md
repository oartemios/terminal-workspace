# Общая грамматика клавиш и локальные defaults

Статус: решение реализации итерации 2.1 по согласованному UX-направлению. Neovim остаётся ориентиром взаимодействия; конкретные defaults изменяемы, копирование всех режимов и команд редактора не требуется.

Общая навигация Core: `h/j/k/l`, Enter, Backspace, Tab/Shift-Tab. В списке `l`/Enter вызывают default Action или открывают список Actions; `h`/Backspace вызывают предоставленный плагином parent invocation. Если родителя нет, `h` возвращает фокус к группам, Backspace остаётся без действия. `/` открывает фильтр, `:` — строку команд, Space — палитру, Esc — отмену/возврат. Leader `,` остаётся текущим default для глобальных команд Core/Workspace.

Files объявляет только локальный `p` → `files.preview`. Defaults `o/u/y` и aliases `fp/fs/fo/fu` удалены: открытие и возврат используют общую навигацию, показ пути доступен через `a` → Show path, палитру и `:files.path`. Все прежние CommandId, Actions и parent invocation сохраняются; предметная логика Files не переносится в Core.

Независимо упакованный Catalog использует тот же путь: `l`/Enter открывают секцию, `h`/Backspace возвращают к индексу. В представлении Introduction локальный `p` → `catalog.read` читает заметку. Прежние defaults `o/u/nrd` удалены. Один символ может иметь собственный смысл в каждом активном плагине; namespace в локальном вводе не нужен.

Не каждому действию нужен отдельный default binding. Справка `?` показывает эффективные локальные bindings и общие способы обнаружения остальных операций. В текстовых режимах локальные bindings не исполняются. Plugin/Group/View scopes, project-local overrides и диагностика конфликтов сохраняются без изменения API v0.3 или JSON version 1.

Удаление defaults не запрещает пользовательские сочетания: overrides могут явно вернуть `fp`, `o/u/y` или другие разрешённые последовательности. Автоматической миграции и перезаписи overrides нет. Копирование в clipboard, undo и новые доменные операции этой итерацией не добавляются.

Проверки используют общую навигацию и новые defaults: Files и Catalog в двух Workspaces, четыре маршрута исполнения, Actions/палитра/командная строка для операций без отдельного binding, восстановление контекста, настройки и активация, scoped overrides, возврат удалённого alias через явный override, конфликты и Unicode. Unix PTY проверяет реальные клавиши, переключение Workspace, resize и восстановление терминала. Performance-цели MVP остаются отдельной задачей этапа 7.

Последующее решение: [этап 3 — executable packages и Plugin API 0.4](0006-executable-plugin-runtime.md) добавляет глобальную установку, lifecycle и расширенную permission model. Ограничения статической загрузки в этом документе описывают состояние на момент исходного решения.
