# Terminal Workspace

Терминальная рабочая среда на Rust. Первый TUI позволяет пройти путь Workspace → Files → Entries → файл → действие с клавиатуры. Контекстные действия, палитра, командная строка и сочетания клавиш выполняют операции через общий реестр команд.

План следующих этапов и критерии завершения: [roadmap до MVP](ROADMAP.md).

## Запуск

```sh
cargo run --offline -- .
```

Аргумент `.` — каталог проекта; можно указать другой локальный каталог. После сборки исполняемый файл находится в `target/debug/tw`. Нужен интерактивный терминал macOS или Linux.

Для первой проверки нажми `/`, введи `README.md`, затем Enter. Нажми `a`, выбери `Preview file` клавишей ↓ и нажми Enter. Esc вернёт к списку файлов. Ту же операцию вызывают клавиша `p`, палитра (Space → `preview` → Enter) и строка `:files.preview README.md`.

Для навигации выдели каталог и нажми Enter или `l`. Backspace или `h` вернёт к родительскому каталогу с выделением каталога, из которого ты вышел. Текущий путь показан над списком; фильтр и выбор сохраняются при повторном открытии каталога. Корень Workspace остаётся границей навигации. Команды `:files.open src` и `:files.parent` выполняют те же переходы.

При размере терминала от 90×16 используется оформление по визуальному референсу: тёмный фон, голубые рамки, фиолетовое выделение и две области. Слева остаётся список объектов, справа — сведения о выбранном объекте, действия, палитра или результат команды. Для предпросмотра файла нажми `p`; Esc вернёт к выбору. Предпросмотр загружается по команде, а не при перемещении выделения. На меньшем терминале используется компактная одноколоночная компоновка. True color зависит от поддержки терминала.

При высоте от 24 строк оформление подробнее повторяет референс: отдельные рамки плагинов и групп, колонки в пропорции 44/56, однострочный нумерованный список с символами типов (▸ каталог, ▤ файл) без разделителей между элементами, заголовок результата, номера строк текста и подсказки клавиш на нижней панели. Для комфортного просмотра используй примерно 140×40 или больше. Показываются только установленные плагины и реальные данные текущего Workspace.

## Управление

Клавиши ниже — выбранные defaults прототипа; это не фиксированный продуктовый контракт.

| Клавиши | Действие |
| --- | --- |
| Tab / Shift-Tab | Фокус между плагинами, группами и списком |
| Стрелки или `h j k l` | Навигация в текущей области |
| Enter / `l` | В списке вызвать default Action (открыть каталог); иначе показать действия |
| Backspace / `h` | В списке вернуться к родительскому контексту, когда он доступен |
| `a` | Контекстные действия |
| Space | Палитра команд с поиском; ↑↓ выбирают команду |
| `:` | Командная строка; без аргумента используется выбранный элемент текущего плагина |
| `/` | Фильтр элементов; Enter принимает, Esc отменяет ввод |
| `s` | Порядок плагина → название по возрастанию → по убыванию |
| `r` | Обновить текущую группу |
| `p` в Files | Preview выбранного файла |
| `, w` / `, b` | Открыть Workspace / вернуться к предыдущему |
| PgUp / PgDn, Home / End | Прокрутка списка, результата и справки |
| Esc | Назад; в списке очищает фильтр |
| `?` | Справка |
| `q`, Ctrl-C, Ctrl-D | Выход (в режиме ввода `q` вводится как текст) |

## Переключение проекта и локальные клавиши

`:core.workspace.open /путь/к/проекту` переключает Workspace без выхода из приложения. Путь с пробелами передаётся целиком; относительный путь считается от текущего проекта. `, w` или команда открытия из палитры запрашивает путь в командной строке. `, b` / `:core.workspace.previous` возвращает к предыдущему проекту. Эти операции также доступны через `a` на вкладках плагинов.

При возврате восстанавливаются вкладка, группа, каталог, выбор, фильтр и порядок в пределах сессии; данные перечитываются. Настройки, разрешения и временное отключение независимы для каждого проекта. Ошибка открытия оставляет текущий Workspace доступным.

В активном плагине его префикс не нужен: Files объявляет локальный `p` для preview. Каталоги открываются через Enter/`l`, возврат — через `h`/Backspace. Полный путь доступен через `a` → Show path, палитру и `:files.path`. Defaults `o/u/y` и старые aliases `fp/fs/fo/fu` удалены; их можно явно задать в пользовательских overrides. `?` показывает эффективные bindings; незавершённая последовательность показывает продолжения, Esc отменяет её. В режиме ввода текста bindings не исполняются. Общая грамматика и актуальные defaults описаны в [решении итерации 2.1](docs/decisions/0005-keyboard-defaults.md).

Настроить сочетания можно в `.terminal-workspace.json`, например `"overrides": {"keybindings": [{"keys":"p","plugin":"files","command":null},{"keys":"vnp","plugin":"files","command":"files.preview"}]}`. `null` отключает старую клавишу, новая последовательность вызывает ту же зарегистрированную команду. Области действия, приоритеты и ограничения описаны в [решении этапа 2](docs/decisions/0004-workspace-switching-and-bindings.md).

## Настройки и плагины

Проект хранит активацию, разрешения и plugin-specific настройки в `.terminal-workspace.json` (version 1). При первом запуске Files включён и получает WorkspaceRead; сохранённый отзыв разрешения после перезапуска сохраняется. Файл создаётся при успешном сохранении defaults или постоянном изменении настроек. Для изменения settings закрой приложение, отредактируй JSON и запусти снова. Схема и ограничения описаны в [решении реализации](docs/decisions/0003-workspace-configuration.md).

`Tab` переводит фокус на вкладки плагинов; `a` показывает операции активации и разрешений. Эти же операции доступны из палитры, строки команд и leader-последовательностей:

| Команда | Клавиши | Результат |
| --- | --- | --- |
| `:core.plugins` | `, p` | Установленные плагины и активация |
| `:core.plugin.suspend files` | `, s` | Отключить до конца сессии |
| `:core.plugin.disable files` | `, d` | Отключить для проекта, сохранив настройки |
| `:core.plugin.enable files` | `, e` | Включить для проекта и сессии |
| `:core.permissions files` | Через палитру или Actions | Запрошенные и выданные разрешения |
| `:core.permission.revoke-read files` | `, r` | Отозвать WorkspaceRead |
| `:core.permission.grant-read files` | `, g` | Выдать WorkspaceRead |

Bindings и палитра используют выбранную вкладку плагина, даже когда в списке нет Item. Явный plugin id в командной строке имеет приоритет. Esc закрывает результат. Отключение последнего активного плагина сохраняет доступ к Core-командам и повторному включению.

При повреждённом файле или неизвестной версии TUI открывается с ошибкой и отключёнными плагинами, запись блокируется до исправления и перезапуска. Ошибка сохранения оставляет прежнее состояние; внешнее редактирование обнаруживается и не перезаписывается. Неизвестные записи плагинов и поля сохраняются.

## Разработка

```sh
cargo test --offline
cargo fmt --check
cargo clippy --offline --all-targets -- -D warnings
```

После `cargo build --offline` можно выполнить `python3 tests/tui_pty.py`: проверяется реальный Unix PTY, ввод Unicode, стрелки, Esc, изменение размера и восстановление терминала после `q`, Ctrl-C и Ctrl-D.

`src/lib.rs` — Workspace, разрешения, состояние плагинов и реестр команд. `src/bindings.rs` — области действия, overrides и конфликты bindings. `src/files.rs` — предметная логика Files. `src/ui.rs` — состояние, навигация и рендер TUI. `src/terminal.rs` — ввод, размер терминала и восстановление его настроек. `tests/` проверяет ядро и клавиатурные сценарии интерфейса.

Технический выбор терминального слоя описан в [решении реализации](docs/decisions/0001-terminal-ui.md).

[Draft Plugin API v0.3](docs/plugin-api.md) проверяется на независимо упакованном [custom plugin](examples/custom-plugin/README.md). Его тесты запускаются отдельно:

```sh
cargo test --offline --manifest-path examples/custom-plugin/Cargo.toml --target-dir target/custom-plugin
```

## Текущие границы

Files показывает содержимое каталогов внутри Workspace и первые 8 KiB файла. Активация и WorkspaceRead сохраняются в `.terminal-workspace.json`; временное отключение живёт до конца сессии. Settings и keybinding overrides редактируются вручную и применяются при открытии проекта. Состояние UI между запусками не сохраняется; bindings пока поддерживают только последовательности печатных символов без пробелов. Плагины связаны с процессом Rust через trait: проверки разрешений не изолируют недоверенный код. Custom plugin упакован отдельно как Rust crate; глобальная установка, динамическая загрузка и асинхронные сетевые операции относятся к следующим этапам.
