# Terminal Workspace

Терминальная рабочая среда на Rust. TUI позволяет пройти путь Workspace → Plugin → Group → Item → Action с клавиатуры. Files предоставляет навигацию и preview, устанавливаемый Git — Status, Branches и diff. Контекстные действия, палитра, командная строка и сочетания клавиш выполняют операции через общий реестр команд.

План следующих этапов и критерии завершения: [roadmap до MVP](ROADMAP.md).

## Запуск

```sh
cargo run --offline -- .
```

Аргумент `.` — каталог проекта; можно указать другой локальный каталог. После сборки исполняемый файл находится в `target/debug/tw`. Нужен интерактивный терминал macOS или Linux.

При первом запуске Files устанавливается в глобальный каталог `~/.local/share/terminal-workspace/plugins`, получает доверие как явный bundled default и включается для проекта. `TW_PLUGIN_DIR` задаёт альтернативный абсолютный путь. После явного uninstall Files автоматически не возвращается. Код пакетов не хранится в Workspace.

Для первой проверки нажми `/`, введи `README.md`, затем Enter. Нажми `a`, выбери `Preview file` клавишей ↓ и нажми Enter. Esc вернёт к списку файлов. Ту же операцию вызывают клавиша `p`, палитра (Space → `preview` → Enter) и строка `:files.preview README.md`.

Для навигации выдели каталог и нажми Enter или `l`. Backspace или `h` вернёт к родительскому каталогу с выделением каталога, из которого ты вышел. Текущий путь показан над списком; фильтр и выбор сохраняются при повторном открытии каталога. Корень Workspace остаётся границей навигации. Команды `:files.open src` и `:files.parent` выполняют те же переходы.

При размере терминала от 90×16 используется оформление по визуальному референсу: тёмный фон, голубые рамки, фиолетовое выделение и две области. Слева остаётся список объектов, справа — сведения о выбранном объекте, действия, палитра или результат команды. Для предпросмотра файла нажми `p`; Esc вернёт к выбору. Предпросмотр загружается по команде, а не при перемещении выделения. На меньшем терминале используется компактная одноколоночная компоновка. True color зависит от поддержки терминала.

При высоте от 24 строк оформление подробнее повторяет референс: отдельные рамки плагинов и групп, колонки в пропорции 44/56, однострочный нумерованный список с символами типов (▸ каталог, ▤ файл) без разделителей между элементами, заголовок результата, номера строк текста и подсказки клавиш на нижней панели. Для комфортного просмотра используй примерно 140×40 или больше. Показываются только установленные плагины и реальные данные текущего Workspace.

## Управление

Клавиши ниже — выбранные defaults прототипа; это не фиксированный продуктовый контракт.

| Клавиши | Действие |
| --- | --- |
| Tab / Shift-Tab | Фокус между плагинами, группами и списком |
| Стрелки или `h j k l` | Навигация в текущей области |
| Enter / `l` | В списке вызвать default Action (открыть каталог); иначе показать действия |
| Backspace / `h` | В списке вернуться к родительскому контексту, когда он доступен |
| `a` | Контекстные действия |
| Space | Палитра команд с поиском; ↑↓ выбирают команду |
| `:` | Командная строка, включая просмотр результата и справку; без аргумента используется выбранный элемент текущего плагина |
| `/` | Фильтр элементов; Enter принимает, Esc отменяет ввод |
| `s` | Порядок плагина → название по возрастанию → по убыванию |
| `r` | Обновить текущую группу |
| `p` в Files | Preview выбранного файла |
| `, w` / `, b` | Открыть Workspace / вернуться к предыдущему |
| PgUp / PgDn, Home / End | Прокрутка списка, результата и справки |
| Esc | Назад; в списке очищает фильтр |
| `?` | Справка |
| `q`, Ctrl-C, Ctrl-D | Выход (в режиме ввода `q` вводится как текст) |

## Переключение проекта и локальные клавиши

`:core.workspace.open /путь/к/проекту` переключает Workspace без выхода из приложения. Путь с пробелами передаётся целиком; относительный путь считается от текущего проекта. `, w` или команда открытия из палитры запрашивает путь в командной строке. `, b` / `:core.workspace.previous` возвращает к предыдущему проекту. Эти операции также доступны через `a` на вкладках плагинов.

При возврате восстанавливаются вкладка, группа, каталог, выбор, фильтр и порядок в пределах сессии; данные перечитываются. Настройки, разрешения и временное отключение независимы для каждого проекта. Ошибка открытия оставляет текущий Workspace доступным.

В активном плагине его префикс не нужен: Files объявляет локальный `p` для preview. Каталоги открываются через Enter/`l`, возврат — через `h`/Backspace. Полный путь доступен через `a` → Show path, палитру и `:files.path`. Defaults `o/u/y` и старые aliases `fp/fs/fo/fu` удалены; их можно явно задать в пользовательских overrides. `?` показывает эффективные bindings; незавершённая последовательность показывает продолжения, Esc отменяет её. В режиме ввода текста bindings не исполняются. Общая грамматика и актуальные defaults описаны в [решении итерации 2.1](docs/decisions/0005-keyboard-defaults.md).

Настроить сочетания можно в `.terminal-workspace.json`, например `"overrides": {"keybindings": [{"keys":"p","plugin":"files","command":null},{"keys":"vnp","plugin":"files","command":"files.preview"}]}`. `null` отключает старую клавишу, новая последовательность вызывает ту же зарегистрированную команду. Области действия, приоритеты и ограничения описаны в [решении этапа 2](docs/decisions/0004-workspace-switching-and-bindings.md).

## Настройки и плагины

Проект хранит активацию, разрешения и plugin-specific настройки в `.terminal-workspace.json` (version 1). При первом запуске Files включён и получает WorkspaceRead; сохранённый отзыв разрешения после перезапуска сохраняется. Файл создаётся при успешном сохранении defaults или постоянном изменении настроек. Для изменения settings закрой приложение, отредактируй JSON и запусти снова. Схема и ограничения описаны в [решении реализации](docs/decisions/0003-workspace-configuration.md).

`Tab` переводит фокус на вкладки плагинов; `a` показывает операции активации и разрешений. Эти же операции доступны из палитры, строки команд и leader-последовательностей:

| Команда | Клавиши | Результат |
| --- | --- | --- |
| `:core.plugins` | `, p` | Installation, Workspace/session activation, availability и connection |
| `:core.plugin.suspend files` | `, s` | Отключить до конца сессии |
| `:core.plugin.disable files` | `, d` | Отключить для проекта, сохранив настройки |
| `:core.plugin.enable files` | `, e` | Включить для проекта и сессии |
| `:core.permissions files` | Через палитру или Actions | Запрошенные и выданные разрешения |
| `:core.permission.revoke files WorkspaceRead` | `, r` | Отозвать WorkspaceRead |
| `:core.permission.grant files WorkspaceRead` | `, g` | Выдать WorkspaceRead |
| `:core.plugin.install /путь/к/пакету` | Через палитру | Установить пакет без запуска |
| `:core.plugins.discover` | Через палитру | Перечитать глобальный каталог |
| `:core.plugin.trust files` / `untrust files` | Через палитру или Actions | Разрешить / запретить запуск native executable |
| `:core.plugin.restart files` | Через палитру или Actions | Повторить запуск после сбоя |
| `:core.plugin.uninstall files` | Через палитру или Actions | Удалить пакет, сохранив настройки проекта |

Категории разрешений: `WorkspaceRead`, `WorkspaceWrite`, `Process`, `Network`, `Credentials`, `Environment`. Host проверяет все объявленные категории перед запуском. Это не OS sandbox: trusted executable имеет права пользователя ОС. Старые `grant-read`/`revoke-read` остаются aliases общего маршрута. Отзыв разрешения, suspend, disable и uninstall останавливают worker и его группу процессов в текущем приложении.

Bindings и палитра используют выбранную вкладку плагина, даже когда в списке нет Item. Явный plugin id в командной строке имеет приоритет. Esc закрывает результат. Отключение последнего активного плагина сохраняет доступ к Core-командам и повторному включению.

При повреждённом файле или неизвестной версии TUI открывается с ошибкой и отключёнными плагинами, запись блокируется до исправления и перезапуска. Ошибка сохранения оставляет прежнее состояние; внешнее редактирование обнаруживается и не перезаписывается. Неизвестные записи плагинов и поля сохраняются.

## Разработка

```sh
cargo test --offline
cargo fmt --check
cargo clippy --offline --all-targets -- -D warnings
```

После `cargo build --offline` можно выполнить `python3 tests/tui_pty.py`: проверяется реальный Unix PTY, ввод Unicode, стрелки, Esc, изменение размера и восстановление терминала после `q`, Ctrl-C и Ctrl-D.

`src/runtime/` — установка пакетов, процессный runtime и SDK сервера. `src/lib.rs` — Workspace, разрешения, состояние плагинов и реестр команд. `src/bindings.rs` — области действия, overrides и конфликты bindings. `src/files.rs` и `src/git.rs` — предметная логика Files и Git. `src/ui.rs` — состояние, навигация и рендер TUI. `src/terminal.rs` — ввод, размер терминала и восстановление его настроек. `tests/` проверяет ядро и клавиатурные сценарии интерфейса.

Технический выбор терминального слоя описан в [решении реализации](docs/decisions/0001-terminal-ui.md).

[Draft Plugin API v0.5](docs/plugin-api.md) проверяется на независимо упакованном [custom plugin](examples/custom-plugin/README.md). Его тесты запускаются отдельно:

```sh
cargo test --offline --manifest-path examples/custom-plugin/Cargo.toml --target-dir target/custom-plugin
```

## Пакеты плагинов

Пакет — `plugin.json` и один executable; JSON-lines protocol 1 описан в [контракте](docs/plugin-protocol.md). Установка и discovery не запускают код. Для внешнего пакета отдельно выдаются trust, Workspace activation и запрошенные permissions. Пример сборки и установки без пересборки `tw`: [Catalog](examples/custom-plugin/README.md).

CLI доступен без TUI:

```sh
target/debug/tw plugins install /путь/к/пакету
target/debug/tw plugins list
target/debug/tw plugins trust catalog
```

CLI также поддерживает `untrust <id>`, `uninstall <id>` и `package-files <новый-каталог>`. Он меняет глобальную установку; активация для проекта задаётся в TUI. Files использует тот же процессный контракт, что Catalog.

## Git

Git устанавливается явно и не активируется автоматически при обнаружении репозитория. После `cargo build --offline` создай пакет в новом каталоге и установи его:

```sh
target/debug/tw plugins package-git /tmp/tw-git-package
target/debug/tw plugins install /tmp/tw-git-package
target/debug/tw plugins trust git
target/debug/tw .
```

В TUI выполни команды (Esc закрывает каждый результат):

```text
:core.plugin.enable git
:core.permission.grant git WorkspaceRead
:core.permission.grant git Process
```

Перейди на вкладку Git через Tab и стрелки. Группа Status показывает Git-коды состояния `XY`: первая позиция — индекс, вторая — рабочее дерево; `??` — untracked. Выбери файл и нажми `p` или Enter для diff. Staged и unstaged изменения показаны отдельными секциями; untracked файл сравнивается с пустым содержимым. Переименования сохраняют исходное и новое имена. Та же операция доступна через `a` → View file diff, Space → `git.diff` и `:git.diff путь с пробелами`.

В Branches показаны локальные ветки; `*` отмечает текущую. `p`, Enter или `a` → View branch details показывают последний commit. Команда — `:git.branch refs/heads/main`; палитра ищет `git.branch`. В detached HEAD ни одна ветка не отмечена текущей. В новом репозитории без commits группа Branches пуста. `r` обновляет текущую группу; фильтр, сортировка и навигация работают как в Files.

Эта итерация предоставляет просмотр без stage, commit и переключения веток. Требуется установленный `git` в стандартном системном PATH и Workspace в корне рабочего репозитория. Git работает локально без сетевых запросов. Вывод каждого процесса ограничен 128 KiB; превышение даёт ошибку. Пути и текст должны быть UTF-8. Ошибка репозитория или отказ permissions не мешают Files. Технические решения и ограничения: [Git-плагин](docs/decisions/0007-read-only-git-plugin.md).

## Текущие границы

Files показывает содержимое каталогов внутри Workspace и полностью загружает preview файлов до 128 KiB. Прокрутка: `j/k` или ↑↓, страницы — PgUp/PgDn, начало/конец — Home/End. Более крупный файл даёт явную ошибку вместо частичного текста. Предел оставляет место для JSON escaping внутри лимита ответа runtime 1 MiB. Settings и keybinding overrides редактируются вручную и применяются при открытии проекта. UI-состояние между запусками не сохраняется; bindings поддерживают последовательности печатных символов без пробелов.

В просмотре результата и справке `:` открывает командную строку поверх текущего содержимого. Esc или пустой Enter возвращает к прежней позиции; ошибка команды сохраняет просмотр и показывает сообщение. Успешная команда показывает новый результат или выполняет переход через общий CommandRegistry.

В просмотре результата `/` открывает поиск по исходному тексту: введи текст и нажми Enter. Поиск буквальный, учитывает регистр; `n` и `N` переходят к следующей/предыдущей совпавшей строке с возвратом через границы документа. Совпавшая строка выделяется, статус показывает номер совпадения. Пустой поиск очищает запрос. В списке файлов `/` по-прежнему фильтрует имена.

`g` запрашивает номер исходной строки; `:120` сразу переходит к строке 120. Esc отменяет ввод, неверный номер не закрывает документ. Эквивалентные registered команды: `:core.view.find текст`, `:core.view.goto 120`, `:core.view.next`, `:core.view.previous`, `:core.view.source`.

Files объявляет `.md`/`.markdown` как Markdown: заголовки выделены, списки и цитаты оформлены, блоки кода сохраняют буквальный текст, inline-разметка упрощается и ссылки показывают адрес. Длинные строки переносятся в пределах панели. Номер исходной строки показан один раз, у продолжений он пустой. `v` переключает оформление и исходник; номера, поиск и переход относятся к исходным строкам, даже если строка занимает несколько строк терминала. Это базовое терминальное оформление: таблицы и неподдерживаемая разметка остаются текстом; HTML и изображения не рендерятся. Другие плагины могут использовать тот же renderer через `Block.format`.

Пакеты — доверяемые пользователем native executables без OS sandbox. Host проверяет объявленные permissions, ограничивает environment и предоставляет проверяемые path helpers SDK; прямой доступ executable к ОС этим не изолирован. Credentials пока передаются только по явно указанным именам environment variables, без keychain/vault. Requests синхронны с deadline 1 s, handshake — 5 s: медленный worker может временно задержать TUI. Async и GitHub ещё не реализованы. Performance-цели MVP не достигнуты/не подтверждены; debug PTY startup около 1.06 s при проверке этапа 3. Ограничения и измерения: [решение runtime](docs/decisions/0006-executable-plugin-runtime.md).
